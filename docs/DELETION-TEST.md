## What the deletion test does

For each example vault it:

1. copies every `.md` file to a temporary directory,
2. **deletes every non-markdown file**, by construction — only markdown
   is ever copied,
3. re-runs the full lint over the stripped copy,
4. fails if the result is not clean.

## What it proves

That the laws, the schema, the scheduler state and the whole vocabulary
survive the removal of every tool. The vault is still readable with
`cat`, still greppable, still writable by hand.

## What it does NOT prove

Read this part; a test that only advertises its strengths is marketing.

- **It does not prove the tools are unnecessary.** `bin/` is optional in
  the sense that the vault works without it, not in the sense that the
  scheduler is nice to have. FSRS would schedule better.
- **It does not prove portability of format.** The schema is a
  documented convention in this repository. Markdown itself is portable;
  `type: proof` is not a standard, and a future editor will not know it.
- **It does not prove you learned anything.** It proves the record is
  intact and the laws are enforced. Whether a claim in it is true and
  retained is a question about the reader, which no linter can answer.
- **It does not cover the git history**, which is a second durable store
  this project leans on and does not test.
- **A passing run is a floor, not a ceiling.** It shows the laws are
  checked. It does not show the laws are the right laws.
