# 04 — The Ontology

**One primitive: an idea you must earn the right to hold.**

Learning earns that right from a source. Cognitive work earns it from
experience. Same machinery, two kinds of raw. There is no second ontology to
learn, because a person who has to learn the system twice has already lost.

## Vault layout

```
<vault>/
  subject.md              the vault's top-level note
  today.md                generated by bin/g-today — never hand-edited
  attention-log.md        The Log — append-only
  sources/<subject>/*.md  provenance records (committed, paraphrased)
  raw/                    verbatim material — NEVER committed
  self/                   your own prior reasoning — committed
  claims/<subject>/*.md
  attempts/<subject>/*.md
  proofs/<subject>/*.md
  predictions/<subject>/*.md
  errors/<subject>/*.md
  insights/<subject>/*.md
  practices/*.md
  audits/*.md
```

### `raw/` versus `sources/` — the three layers

`raw/` holds the **bytes**: the book, the paper, the article. It is gitignored
and it is the only thing this project refuses to track. It is yours.

`sources/` holds a `source` note: an **original, paraphrasing provenance
record**. Author, title, year, and a chapter or section locator. Committing it
tells you *where to look* without redistributing anything. This is the middle
layer of the three-layer pattern in [cite: karpathy_llmwiki], and the reason a
`sources/` note is a legitimate thing to put in a public repository.

`claims/` holds the compiled third layer, gated behind a recorded failure by
Law 1.

### `self/`

Your own prior reasoning — past notes, past predictions, past decisions. **Not
gitignored.** Your thinking is durable state; if it lives in a directory marked
ephemeral, the system has failed at the only thing it promised. `.gitignore`
ignores `raw/` and nothing else that could hold knowledge.

## Common fields

Every note, all ten types, carries exactly these:

| Field | Type | Rule |
|---|---|---|
| `type` | one of the ten names below | required |
| `id` | `kebab-case` string, unique in the vault | required |
| `title` | string | required |
| `created` | `YYYY-MM-DD` | required |
| `updated` | `YYYY-MM-DD` | required, `>= created` |

`id` is the only identifier the system uses. There are no cross-file numeric
IDs to drift out of sync, and `id` is greppable from a terminal in the year 2040
when the tool that generated it is gone.

## The ten note types

Notation: **R** = required, **O** = optional. "id" in a field's type means
"another note's `id`". A field marked *gated* is subject to a law.

### 1. `subject`

A field of study. One per vault, realistically.

| Field | Type | Req |
|---|---|---|
| `state` | `state` enum | R |
| `milestone_earned` | `true` \| `false` | R |
| `core_ideas` | list of strings — the authoritative "core ideas index" | O |

`milestone_earned: true` requires at least one `transfer`-rung proof
somewhere in the subject. Enforced by `L4`.

The `core_ideas` list is deliberately copied from a pattern worth stealing: seed
a syllabus from an authoritative list of the field's core concepts rather than
letting a language model invent a curriculum from its training data. If you have
no such list, say so in the note. An invented index is a strawman to correct, not
a truth.

### 2. `source`

A provenance record for one work. **Not** the work.

| Field | Type | Req |
|---|---|---|
| `locator_hint` | string — how to find a passage in the original | O |
| `summary` | string | **gated by Law 2** |

`summary` may not be present until an `attempt` referencing this source exists.
Enforced by `L2`. This is the note that makes "read it yourself first" a
structural property rather than a piece of advice.

### 3. `claim`

A compiled assertion. The spine of the vault.

| Field | Type | Req |
|---|---|---|
| `state` | `state` enum | R |
| `status` | `draft` \| `compiled` | R |
| `unlocked_by` | id \| `null` | R (**may be null**) |
| `source` | id \| `null` | R (**may be null**) |
| `locator` | string \| `null` | R (**may be null**) |
| `kind` | `source` \| `inference` \| `null` | R (**may be null**) |
| `due` | `YYYY-MM-DD` \| `null` | R (**may be null**) |
| `last_review` | `YYYY-MM-DD` \| `null` | R (**may be null**) |
| `lapses` | integer `>= 0` | R |
| `stability` | string — display only, e.g. `1w` | R |
| `difficulty` | integer `1..10` | R |

Three of these are required but *nullable*, and the distinction matters: the key
must be **present and empty** for a `draft`, and **present and non-empty** for a
`compiled`. Absence is not the same as `null` here, and `L1`/`L3` depend on it.

A claim with `status: compiled` and `kind: null` is saying "this came from
somewhere but I did not record where". That is a `draft` wearing a `compiled`
hat, and `L3` fails it.

### 4. `proof`

Evidence that the learner earned a claim.

| Field | Type | Req |
|---|---|---|
| `claim` | id of a `claim` | R |
| `rung` | `recall` \| `derive` \| `transfer` | R |
| `artifact` | string — where the learner's own attempt lives | R |
| `verified` | `YYYY-MM-DD` \| `null` | R |

`artifact` is **yours, not the agent's**. A proof the model wrote is not a proof
you produced, and a system that accepts one has no evidence layer at all.

### 5. `attempt`

An attempt before the answer. This is the key to Law 1.

| Field | Type | Req |
|---|---|---|
| `claim` | id of a `claim` | R |
| `outcome` | `passed` \| `failed` \| `null` | R |
| `artifact` | string | R |

`outcome: failed` is the most valuable field in the schema. It is what unlocks
the compiled claim, and therefore what makes the whole system work. It must
therefore be **cheap and unpunished** — if recording a failure feels like losing,
nobody records one, and Law 1 quietly becomes "the answer is always open". `L1`
accepts either an `attempt` or an `error` as the key, for the same reason.

### 6. `error`

A recorded mistake, held forever.

| Field | Type | Req |
|---|---|---|
| `recorded_at` | `YYYY-MM-DD` | R |
| `resolution` | `open` \| `corrected` \| `superseded` | R |
| `supersedes` | id \| `null` | R |
| `claim` | id \| `null` | O |

**`erased` is not a legal value for `resolution`, and the vocabulary is closed.**
`L5` enforces both. A correction is a new `error` note with
`resolution: superseded` pointing at the old one via `supersedes`. Nothing is
overwritten. Ever. That is Law 5 and it is the whole reason the record is worth
anything.

### 7. `prediction`

A dated, falsifiable claim about the world.

| Field | Type | Req |
|---|---|---|
| `statement` | string | R |
| `date` | `YYYY-MM-DD` | R |
| `outcome` | `open` \| `confirmed` \| `refuted` | R |
| `refuted_by` | id \| `null` | R |

The cheapest high-value note type in the schema. A dated prediction is a
falsifiable instrument; when it comes back `refuted`, it drags the claim it was
about into `retracted` and leaves both records standing.

### 8. `insight`

Something you noticed that is not yet a claim.

| Field | Type | Req |
|---|---|---|
| `claim` | id \| `null` | R |
| `related` | list of ids | O |

Deliberately the loosest type, because premature structure is a form of
resistance to thinking. An insight that never becomes a claim is still a record
that you had it.

### 9. `practice`

A repeated physical or cognitive practice. Same proof discipline as a concept.

| Field | Type | Req |
|---|---|---|
| `cadence` | string — e.g. `3x/week`, `daily` | R |
| `state` | `state` enum | R |
| `due` | `YYYY-MM-DD` \| `null` | R |
| `last_review` | `YYYY-MM-DD` \| `null` | R |
| `lapses` | integer `>= 0` | R |
| `stability` | string | R |
| `difficulty` | integer `1..10` | R |
| `proof` | id \| `null` | R |

**A practice is done when there is a proof artifact, not when a box is ticked.**
See [`02-two-disciplines.md`](02-two-disciplines.md). This is what stops the
brain half of the system from decaying into a habit checklist — which would be
the same manufactured-feeling-of-progress failure the whole design rejects.

### 10. `audit`

The result of reading The Log back. **Frequencies only.**

| Field | Type | Req |
|---|---|---|
| `period` | string, e.g. `2026-W39` | R |
| `from` | `YYYY-MM-DD` | R |
| `to` | `YYYY-MM-DD` | R |

If an `audit` note contains a score, a grade, or a judgement attached to a
number, it violates the discipline. `L11` will reject the fields; it cannot
reject prose, which is why [`02-two-disciplines.md`](02-two-disciplines.md)
specifies the register in words.

## The state machine

One vocabulary, used by `subject`, `claim`, and `practice`:

`unseen` · `attempted` · `failed` · `proven` · `decaying` · `re-attempting` ·
`retracted`

### Legal transitions — and nothing else

| From | To | Trigger |
|---|---|---|
| `unseen` | `attempted` | an `attempt` note was written |
| `attempted` | `failed` | `attempt.outcome: failed` |
| `attempted` | `proven` | a `proof` note exists |
| `attempted` | `re-attempting` | you came back later |
| `failed` | `re-attempting` | the Closed Book is open; you tried again |
| `failed` | `proven` | a `proof` note exists |
| `proven` | `decaying` | `due` has passed |
| `proven` | `retracted` | an `error` with `resolution: superseded` points here |
| `decaying` | `re-attempting` | a session opened on it |
| `re-attempting` | `proven` | a new `proof` note exists |
| `re-attempting` | `failed` | failed again |
| `re-attempting` | `retracted` | superseded |
| `retracted` | `attempted` | revisited deliberately — **the old proof stays** |

**Nothing transitions to `unseen`.** Nothing un-learns. `retracted` is reachable
but is not a dead end, because you can always revisit — you just cannot un-see
what killed it.

### The rung penalty

If a `claim` carries a `transfer`-rung proof **and** an `attempt` with
`outcome: failed` dated *after* that proof's `verified` date, then the claim may
**not** be `proven`. It must be `failed` or `re-attempting`. Proving something
and then failing it demotes you; it does not leave you where you were.

Enforced by `L4`. This is the mechanical half of "mastery is not a checkbox".

### Why `failed` is a first-class state

Because it is the **only** thing that unlocks the compiled claim. If failure
were a status to be avoided, the Closed Book would be permanently locked and
Law 1 would be theatre. Failure must be the cheapest, most routine thing you
do here.
